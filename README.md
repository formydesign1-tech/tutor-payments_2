# Учёт оплат репетитора

Сайт, куда репетитор загружает выгрузку заказов из Tilda. По ней считаются план по расписанию, факт оплат и сколько каждый ученик ещё должен доплатить, по месяцам и по ученикам.

Это те же расчёты, что в Excel-таблице «Учёт оплат репетитора». Тест `core.test.js` проверяет, что на примере данных итоги совпадают с Excel.

## Как это работает

- Вход один, по общему паролю (`APP_PASSWORD`). Сессия живёт 30 дней в httpOnly-cookie.
- Выгрузка Tilda (xlsx или csv) читается в браузере и уходит на сервер списком платежей. Платёж узнаётся по номеру платежа (`paymentid`), поэтому повторная загрузка не создаёт дублей.
- Ученики из новых платежей добавляются в список сами. Начало занятий, дни и занятий в неделю вписываются на вкладке «Ученики».
- Данные лежат в одном файле `DATA_DIR/db.json`. Запись атомарная, изменения идут по очереди.
- Кнопки «Скачать резервную копию» и «Восстановить из копии» внизу страницы работают с этим же файлом.

## Запуск локально

```bash
npm install
cp env.example .env         # задай APP_PASSWORD
export $(grep -v '^#' .env | xargs)
npm start                   # http://localhost:3000
npm test                    # проверка расчётов и API
```

Нужен Node.js 20 или новее.

## Деплой на Railway

1. Залей проект в GitHub-репозиторий (в `.gitignore` уже есть `node_modules`, `data` и `.env`; если файла `.gitignore` нет, создай его с этими тремя строками).
2. В Railway: **New Project → Deploy from GitHub repo**, выбери репозиторий. Сборку и запуск Railway определит сам (`npm start`, проверка `/healthz` описана в `railway.json`).
3. Открой сервис → **Variables** и добавь:
   - `APP_PASSWORD` — пароль для входа;
   - `DATA_DIR` — `/data`.
4. Открой **Settings → Volumes → New Volume** и примонтируй том в `/data`. Без тома файл с данными пропадёт при следующем деплое.
5. **Settings → Networking → Generate Domain** даст ссылку на сайт. Её и пароль можно отдать репетитору.
6. Первый вход: открой сайт, войди, внизу нажми «Восстановить из копии» и выбери файл резервной копии со своими данными. Либо начни с нуля: загрузи выгрузку Tilda, ученики создадутся из платежей.

Один экземпляр сервиса достаточно. Не запускай несколько реплик: данные лежат в файле на одном томе.

## Рассылка должникам через бота

1. Вкладка «Ученики» → «Загрузить ники из списка»: загрузите файл со списком учеников (колонки «ФИО ученика», «Ник», «Имя»). Ученики сопоставляются по ФИО, ники и имена записываются в карточки. Ник и имя можно править и вручную.
2. Вкладка «Сводка» → карточка «Выгрузка должников для бота» → «Скачать Excel». Дата отчёта и режим берутся сверху страницы.
3. Файл: лист «Оплаты», колонки Ник, Имя, Месяц, Сумма. Одна строка на каждый месяц, за который есть недоплата. В файл не попадают ученики на паузе и завершившие, а также ученики без ника или с ником, который не может быть Telegram-ником (не латиница, короче 5 символов). Они перечислены в карточке.
4. «Скачать с датами занятий» добавляет колонки «Занятий» (сколько неоплачено) и «Даты занятий» (например «21.10, 26.10, 28.10»). Оплата закрывает занятия месяца по порядку, поэтому в долг идут последние даты. Дни берутся из расписания ученика с учётом изменений. Чтобы бот использовал новые колонки в тексте сообщения, его нужно доработать.

## Список учеников в Excel и изменения в расписании

- Вкладка «Ученики» → «Скачать список (Excel)»: все столбцы по каждому ученику (контакты, ник, расписание, цена, скидка, статус, план, оплачено, баланс, долг) и вторым листом все изменения расписания.
- Кнопка «Изменить» в строке ученика открывает его изменения. «Не ходит» с даты (и по дату, если перерыв временный) или «Ходит по-другому» с даты: новые дни, число занятий в неделю, цена. Основное расписание не трогается: до изменения и после периода с датой «по» ученик занимается по нему. Без даты «по» изменение действует до следующего изменения. План, оплаты и долг пересчитываются сразу.

### Напоминания после занятий

Сайт напоминает о долгах не каждый день, а после занятий. Занятие считается прошедшим в конце дня (по расписанию с учётом изменений).

- Вверху страницы жёлтая плашка «Пора напомнить о долге»: ученики с долгом, у которых после последнего напоминания было занятие. Тем, кому ещё не напоминали, напоминание подходит сразу.
- В карточке выгрузки по умолчанию только такие ученики. Флажок «Показать всех должников» возвращает полный список.
- После отправки в бот нажмите «Отметить как отправленные». Эти ученики исчезнут из списка до следующего занятия. Если долг изменился из-за платежа или пересчёта, а нового занятия не было, напоминания нет.
- Отметка ставится на дату отчёта (но не позже сегодняшней). «Сбросить журнал напоминаний» очищает отметки у всех.
- Журнал хранится вместе с данными на Volume и входит в резервную копию. Восстановление из старой копии без журнала его не стирает.
- Ученики без ника или с неподходящим ником в файл не попадают и остаются в плашке, пока ник не исправят.

## Структура

Все файлы лежат в корне проекта, без вложенных папок: так их проще загрузить на GitHub через браузер.

```

core.test.js, server.test.js     Тесты (npm test)
sample-data.json, sample-tilda.csv   Пример данных без имён и пример выгрузки Tilda
env.example        Пример переменных окружения
```

## API

Все запросы, кроме `/healthz` и `/api/login`, требуют cookie после входа. Запись принимает только `application/json`.

| Метод и путь | Что делает |
|---|---|
| `POST /api/login` | `{ password }`, ставит cookie |
| `POST /api/logout` | сбрасывает cookie |
| `GET /api/state` | `{ students, payments, rev }` |
| `PUT /api/students` | `{ students }`, заменяет список учеников |
| `POST /api/payments/import` | `{ rows }`, добавляет и обновляет платежи, создаёт новых учеников |
| `POST /api/payments/delete` | `{ id }`, удаляет платёж |
| `GET /api/export` | резервная копия `{ students, payments }` |
| `POST /api/import` | `{ students, payments }`, заменяет все данные |

## Как считаются деньги

- **План** месяца: число занятий по расписанию (день недели × даты с начала занятий) × цена занятия × (1 − скидка по промокоду). Если дней в расписании больше, чем занятий в неделю, занятия пропорционально уменьшаются; точные дни можно вписать в колонку «Дни, в которые ходит».
- **Факт**: оплаченные занятия закрывают месяцы по порядку, поэтому оплата «за сентябрь», превышающая сентябрь, покрывает и октябрь. Деньги за месяц делятся пропорционально закрытым занятиям.
- **Нужно доплатить**: по каждому месяцу доля плана, соответствующая неоплаченным занятиям. Считается до месяца отчёта включительно.
- **Режим «занятия до даты»**: в месяце отчёта учитываются только занятия, которые уже должны были пройти. **«Месяц целиком»**: весь месяц, как при оплате вперёд.
- Из выгрузки Tilda берутся только строки с заполненной колонкой `paymentid`: это платежи, которые точно прошли. Остальные строки (брошенные корзины, неудачные оплаты) пропускаются, количество пропущенных показывается после загрузки. Номер платежа (`paymentid` без префикса `custom.atolpay:`) служит ключом для защиты от дублей.

Годы: расчёт идёт по месяцам 2026 и 2027 годов (`Y0` и `NM` в начале `core.js`).

## Безопасность и ограничения

- Пароль сравнивается за постоянное время, на вход стоит ограничение 10 попыток за 10 минут с одного IP.
- Заголовки: CSP без внешних скриптов (кроме шрифтов Google), `X-Frame-Options: DENY`, `nosniff`.
- Библиотека `xlsx` 0.18.5 (последняя версия в npm) читает файлы только в браузере репетитора и только те, что он сам выбрал. На сервер Excel не попадает.
- Это один пользователь на одну базу. Для нескольких репетиторов нужна база с аккаунтами (например, Postgres/Supabase), а расчёты из `core.js` переносятся без изменений.
